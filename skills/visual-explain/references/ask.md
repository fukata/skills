# エージェントの質問に資料のページで答える

普段の開発中に Claude Code が AskUserQuestion で、Codex が request_user_input で質問したとき、その質問を資料のページに出す。開発者がページで選んで送ると、その答えが AskUserQuestion の答えとして元のセッションに戻り、作業が続く。ターミナルの選択画面は出ない。

使うには、スキルを入れた後に `bash <skill>/setup.sh` で hook を登録する（Codex は、さらに `/hooks` で信頼する。下の「Codex のとき」）。既定（`auto`）の動きは次のとおり。

- 受け箱を一度でも開いたことがあれば、それ以降の質問は常にページで答えを待つ。質問が来たら（ターミナルに「running PreToolUse hooks…」と出たら）、ブックマークした受け箱を開けば、待っている質問の資料が開く。
- 一度も開いたことが無ければ、受け箱か質問の資料をブラウザで開いているときだけページに出す。開いていなければ、質問はいつもどおりターミナルに出る（受け箱を知らない人の動きは変わらない）。

## 仕組み

```text
セッションを始めたとき、setup.sh が登録したフックが常駐の配信サーバー（serve.py）を起動する（動いていれば何もしない）
  ↓
元のセッションが AskUserQuestion（Codex は request_user_input）を呼ぶ。直前に、フック（scripts/ask_hook.py）が動く
  ↓ 受け箱を開いたことが無く、受け箱も質問の資料も開いていなければ、フックはすぐ終わり、ターミナルに選択画面が出る
フックが質問を配信サーバーに登録する。配信サーバーは質問ごとに資料フォルダを作り、選択肢だけのページを置く
  ↓ 受け箱（/__qa/inbox）を開いていれば、受け箱がその資料を開く。後から受け箱を開いても、待っている質問の資料を開く
  ↓ 同時に、元のセッションを分岐したエージェント（claude -p / codex exec）が、選ぶための図入りの資料を作る（数分。できたらページが差し替わる）
  ↓ 資料には、選択肢の比較の前に質問の背景（何の作業の途中か・聞く理由・決まっていること・判断の軸・答えた後）を置く。検査（check-explanation.py --ask）で欠けていれば差し替えない
開発者がページの右の欄で選んで送る（選ぶ前に、質問欄で選択肢について質問してもよい）
  ↓
フックが答えを受け取り、元のセッションに返す（Claude Code は AskUserQuestion の答えとメモ、Codex は下の「Codex のとき」）。作業が続く
```

- 受け箱は、裏のタブにあっても開いているとみなす（ブラウザは、つないだままの接続を裏のタブでも止めない）。質問の資料を開いている間も同じで、答え終えた後に次の質問が来たら、その資料を開く。
- Claude Code のターミナルには次が出る（フックは待っている間に文を出せないので、固定の文と、待つ前後の知らせで伝える）。Codex は下の「Codex のとき」。
  - セッションの開始: 受け箱を開いたことがあれば、受け箱の URL（「SessionStart:startup says: visual-explain: …」）。
  - 待っている間: スピナーの行に「資料のページで答えを待っています（受け箱から開けます）」。質問の文と選択肢は出ない。
  - ページで答えた後: その質問の資料の URL（後から見返せる）。
  - どれも開発者にだけ見え、会話の文脈（モデル）には入らない。
- ページの「ターミナルで答える」を押すか、待つ時間（既定30分）を過ぎると、フックは何も返さずに終わり、ターミナルにいつもの選択画面が出る。受け箱を開いたことが無い（または `open` の）ときは、受け箱も質問の資料も閉じて30秒たったときも同じ。
- ターミナルで Esc を押してフックを止めると、ページからは答えを送れなくなる（「Claude Code（Codex）がもう答えを待っていない」と出る）。
- 答えが決まったら、作っている途中の資料は止める。
- 「その他」に書いた答えも送れる。複数選べる質問の答えは、選択肢の順に「, 」でつなぐ。メモは AskUserQuestion の `annotations` として渡る。

## 質問が来たことに気づく

- 受け箱と質問の資料のタブのタイトルの先頭に、答えを待っている質問の件数（ほかのセッションの分も）が付く。
- 質問の資料には「ほかに答えを待っている質問 N 件」と、それぞれのリンク・どのセッションの質問か（作業ディレクトリ・ブランチ・最初の依頼）が出続ける。1 つ答えると、次の質問の資料を開く。
- デスクトップ通知: 受け箱を HTTPS で開くと使える（ブラウザは HTTPS か localhost のページにしか通知を許さない）。Tailscale の HTTPS が使える環境なら `ask-config --https on` で、`tailscale serve` が受け箱を `https://<マシン名>.<tailnet>.ts.net:<ポート>` で中継する（配信サーバーは 127.0.0.1 で待ち受ける）。受け箱か質問の資料で「デスクトップ通知を有効にする」を一度押しておくと、タブが裏にあっても、質問が来たときに OS の通知が出て、押すとその資料が開く。
- 音: 受け箱か質問の資料で「音で知らせる」を一度押しておくと、質問が来たときに鳴る（ブラウザは、そのページで一度押した後でないと音を出さない）。
- Orca の端末で動くセッションなら、答えを待っている間、そのワークツリーに Orca のサイドバーの未読の印が付き、ページで答えると外れる（`orca worktree set --unread`。Orca の外では何もしない）。

## 複数のセッション・アカウント

- 配信サーバーと受け箱は 1 つで、すべてのセッションが使う。質問ごとに資料フォルダができ、各セッションのフックは自分の質問の答えだけを受け取る。
- ページと受け箱には、質問したセッションの作業ディレクトリ・ブランチ・最初の依頼の冒頭を出す（同じディレクトリで複数のセッションを動かしていても見分けられる）。1 つ答えると、次に答えを待っている質問の資料を開く。
- 図入りの資料は、別々の質問なら同時に 3 件まで作る。同じ資料への作業（資料作りと質問欄の回答）は 1 件ずつ。
- 別のアカウント（`CLAUDE_CONFIG_DIR` や `CODEX_HOME` を変えて動かすセッション）も、Claude Code と Codex のセッションも、同じ設定・配信サーバー・受け箱を使う。資料作りと質問欄の回答は、質問したセッションのアカウントで動く（その会話を分岐し、使用量もそのアカウントにかかる）。

## 受け箱の URL を伝える

受け箱の URL を聞かれたら、次を引数なしで実行し、出力の「受け箱」の URL（`?k=` 付き）を伝える。この URL で一度開いたブラウザだけが、受け箱と質問の資料を見られ、答えを送れる。

```text
python3 <skill>/scripts/serve.py ask-config
```

- 待ち受けるアドレスの既定は、Tailscale が使えればそのマシンの Tailscale のアドレス、使えなければ `127.0.0.1`（このマシンのブラウザだけ）。それ以外（社内のネットワークのアドレスなど）で見るときは `--bind <アドレス>` を付けて設定する。選び方は [viewing.md](viewing.md)。
- 合言葉は最初に作って設定ファイルに残すので、受け箱の URL は変わらない（ブックマークしてよい）。

## 設定を変える

頼まれたら、上のコマンドに次の引数を付けて実行する。

| 引数 | 意味 |
| --- | --- |
| `--mode auto` | 受け箱を一度でも開いたら常にページで待ち、それまでは `open` と同じ（既定） |
| `--mode open` | 受け箱か質問の資料を開いているときだけページに出す（受け箱を開いたことがあっても） |
| `--mode always`（`--enable`） | 受け箱を開いたことが無くても、常にページで答えを待つ |
| `--mode off`（`--disable`） | 使わない。配信サーバーも止め、セッションを始めても起動しない |
| `--bind <アドレス>` / `--bind auto` | 待ち受けるアドレス。`auto` で既定（Tailscale か `127.0.0.1`）に戻す |
| `--port 8770` | 待ち受けるポート |
| `--wait 30m` | ページの答えを待つ時間（最長約2時間） |
| `--build never` | 図入りの資料を作らず、選択肢だけのページにする（既定 `always` は質問ごとに作る） |
| `--model <名前>` | 資料作りと質問欄の回答に使うモデル |
| `--https on` / `--https off` | 受け箱を Tailscale serve の HTTPS で開けるようにする（デスクトップ通知のため。Tailscale の HTTPS の証明書が使える環境だけ）。`--https-port` でポートを変える |
| `--allow-host <名前>` | IP アドレス・`localhost`・`*.ts.net` 以外のホスト名で開くとき |
| `--stop` | 配信サーバーだけ止める（次にセッションを始めたときに起動する） |

設定は `~/.local/state/visual-explain/ask.json`（`XDG_STATE_HOME` か `VISUAL_EXPLAIN_HOME` で変わる。エージェントやアカウントに依らず同じ）、質問ごとの資料は同じフォルダの `asks/` に残る。締め切ってから30日を過ぎた質問の資料フォルダは、次の質問のときに消す。

## 配信サーバー

- セッションを始めたときに起動し、時間では止まらない。スキルを更新した後は、次にセッションを始めたときに新しい版に入れ替わる。Tailscale を起動・停止して待ち受けるアドレスが変わったときも、次にセッションを始めたときに入れ替わる。
- 受け箱の配信サーバーは、資料のページも含め、合言葉の無い要求には何も返さない（Tailscale のネットワークの他の端末から見えないように）。フォルダの一覧も出さない。
- 資料作りのエージェント（`claude -p` / `codex exec`）は、配信サーバーを起動したセッションの環境変数を引き継ぐ（アカウントの設定フォルダだけは、質問したセッションのものにする）。

## 資料作りの使用量

質問ごとに、元のセッションを分岐したエージェント（`claude -p` / `codex exec`）が資料を作る。元の会話が長いほど、1問ごとの使用量も大きい。質問をページに出さないとき（受け箱を開いたことが無く、開いてもいないとき）は作らない。気になるときは `--build never` にする。資料作りで許すツールは質問欄の回答と同じ（[qa.md](qa.md) の「安全」）。

## 質問するとき

質問のための資料はフックが作る。AskUserQuestion（request_user_input）の前に、質問のためだけの資料を別に作らなくてよい。選択肢の `description` と `preview` は、選択肢だけのページと、資料を作る `claude -p` の両方に渡る。

## Codex のとき

Codex の request_user_input も同じ受け箱で答えられる。Claude Code との違いは次のとおり。

| 項目 | Claude Code | Codex |
| --- | --- | --- |
| フックが受ける質問 | AskUserQuestion | request_user_input（既定では Plan モードでだけ使われる） |
| 複数選択・プレビュー | ある | 無い（1つ選ぶか「その他」に書く） |
| 答えの返り方 | AskUserQuestion の答え（`updatedInput`）とメモ（`annotations`） | ツールの結果を差し替える手段が無いので、フックがツールを拒否（deny）し、その理由の文に答えを入れる。モデルには「Tool call blocked by PreToolUse hook: …これが回答である…」と、request_user_input の結果と同じ形の JSON（`{"answers": {"<id>": {"answers": ["<選んだもの>", "user_note: <メモ>"]}}}`）が届く |
| フックの信頼 | 要らない | setup.sh の後に、Codex を開いて `/hooks` で visual-explain の 2 つのフックを信頼する。信頼するまで、フックは何も言わずに動かない |
| セッションの開始 | 受け箱を開いたことがあれば、ターミナルに受け箱の URL を出す | 何も出さない（SessionStart のフックの出力がモデルの文脈に入るため）。受け箱の URL は `ask-config` で見る |
| 資料作り | `claude -p --resume <ID> --fork-session` | `codex exec fork <ID>`。質問の途中のセッションを分岐できなければ、新しいセッションで作る |
| アカウント | `CLAUDE_CONFIG_DIR` | `CODEX_HOME` |

## うまく動かないとき

| 症状 | 原因と対処 |
| --- | --- |
| 受け箱を開いているのに、いつもの選択画面が出る | 配信サーバーが止まっている、または受け箱を開いたのが前の配信サーバーのとき。受け箱を開き直す。`~/.local/state/visual-explain/ask-hook.log` と `ask-server.log` も見る |
| 質問のたびにターミナルが「running PreToolUse hooks…」で止まる | 受け箱を開いたことがあるので、ページで答えを待っている。受け箱を開いて答えるか、ページの「ターミナルで答える」を押す。開いているときだけにするなら `--mode open` |
| 「起動できない（…を別の配信サーバーが使っている）」 | 別の利用者・別の設定フォルダの配信サーバーが同じポートを使っている。`--port` で別のポートにする |
| 受け箱が「配信サーバーに接続できません」 | 配信サーバーが止まっている。`ask-config` を引数なしで実行すると起動する |
| 受け箱が「案内された URL（?k= 付き）で開き直して」 | 合言葉の無い URL で開いた。`ask-config` の受け箱の URL で開き直す |
| ページに「Claude Code（Codex）がもう答えを待っていない」 | ターミナルで止めた、または待つ時間を過ぎた。ターミナルで答える |
| Codex の質問がページに出ない | `/hooks` でフックを信頼したか、Plan モードで質問させたかを確かめる。同じ場所の `setup.sh` を実行し直しても、フックは同じ位置・同じコマンドのまま（信頼し直しは要らない）。別の場所に入れ直したときと、`teardown.sh` でフックを外した後は、`/hooks` で信頼し直す（Codex は信頼をフックの位置で記録するので、外した後ろにあるほかのフックも信頼し直しが要ることがある） |
| 受け箱が開かない・別の端末から届かない | 待ち受けるアドレスが閲覧側から届かない。[viewing.md](viewing.md) で経路を選び直し、`ask-config --bind` で変える |
