# 資料のページから追加の質問を受ける

資料を `scripts/serve.py` で配信すると、ページの右下に「質問する」ボタンが出て、読み手は資料を開いたまま質問できる。質問には、資料を配信しているマシンで、資料を作ったエージェントが答える（Claude Code は `claude -p`、Codex は `codex exec`。そのマシンでログインしているアカウントの使用量を使う）。資料の説明が足りないと分かったら本文も直し、ページは数秒で最新版に切り替わる。

## 仕組み

```text
ページの質問欄（配信時に serve.py が差し込む qa.js）
  ↓ 質問を送る
serve.py が <資料フォルダ>/qa/qa.json に積み、1件ずつエージェント（claude -p / codex exec）を起動する
  ↓
エージェントが回答を qa/answers/<id>.html に書く。説明不足なら作業用コピー（explanation.qa-draft.html）を直す
  ↓
serve.py が回答と作業用コピーを検査スクリプトにかけ、作業用コピーは通れば本文と差し替える（エラーなら捨てる）
  ↓
ページが数秒おきに状態を取得し、回答を表示する。本文の版が変わっていれば本文を差し替え、直した節を目立たせる
```

- 回答を待つ間: エージェントの途中経過（資料を読んでいる、コードを検索している、本文を直している、検査しているなど）が質問欄に出る。回答後は「調べた手順」に畳んで残る。
- 待機中・作成中の質問は「取り消す」で取り消せる。作成中ならエージェントを止め、本文は変えない。エージェントが終わって回答をまとめている間（検査・本文の差し替え）は取り消せない。
- 回答には続けて質問できる。回答の下の「この回答に質問する」を押すか、回答の中の文字を選んでから質問を書く。続きの質問は元の質問のすぐ下に字下げして並び、エージェントには元の質問と回答（選んだ文字があればそれも）が渡る。続きの質問にも、さらに続けて質問できる。
- 回答が届いたとき、そのタブを見ていなければ、タブのタイトルの先頭に「(1)」のように件数が付く。
- 回答に描いた図の文字のはみ出し、節へのリンク、コードの場所は、検査スクリプト（`--fragment`）で確かめる。問題が残れば、回答に「回答の図・リンクの検査で問題が N 件」と出る。
- 資料とリポジトリの外の情報（一般的な手法・他のツール・文献・チケットやチャット）を問われたら、エージェントは Web の検索・取得と、配信しているマシンのエージェントに設定された MCP のサーバー（Slack・チケット・データベースなど）で調べ、出典を付けて答える。資料とリポジトリだけで答えさせるときは `--local-only` を付けて配信する。

- 回答するセッション: 1問目は、資料を作ったセッション（下の「作成したセッションを記録する」）を、そのエージェントで分岐して答える（Claude Code は `--resume <ID> --fork-session`、Codex は `codex exec fork <ID>`）。記録が無い、または分岐に失敗したら新しいセッションで答える。2問目以降は、1問目のセッションの続きで答える。作成したセッションそのものには書き込まない。
- `explanation.html` そのものには質問欄を書かない。ファイルを直接開いたとき、Orca のプレビュー（[orca.md](orca.md) の経路B）、印刷では質問欄は出ない。
- 質問は全資料で1本の列にして1件ずつ処理する。1件の上限は既定15分。

## 作成したセッションを記録する

資料を作ったら（検査を通した後、配信の前に）、資料フォルダに作成セッションを記録する。`--cwd` には、このセッションの作業ディレクトリ（環境の情報にある Primary working directory）を渡す。

```text
python3 <skill>/scripts/serve.py origin <資料フォルダ> --cwd <このセッションの作業ディレクトリ>
```

セッションの ID は、シェルの環境変数 `CLAUDE_CODE_SESSION_ID`（Codex では `CODEX_THREAD_ID`）から読み、どちらのエージェントか（`agent`）と、アカウントの設定フォルダ（`CLAUDE_CONFIG_DIR` / `CODEX_HOME`。あれば）も一緒に記録する。どちらも無ければ記録せずに終わる（質問には新しいセッションで答える）。同じ作業で資料を作り直したときも、記録は上書きでよい。

## ユーザーに伝えること

配信の URL（[viewing.md](viewing.md) の2）と一緒に、次を短く伝える。

- ページ右下の「質問する」から質問できる。回答は配信しているマシンのエージェント（資料を作ったもの）が書き、そのマシンでログインしているアカウントの使用量を使う。資料を作ったセッションが長いと、1問ごとの使用量も大きくなる。
- 資料の説明が足りなければ本文も直り、ページは自動で最新版に切り替わる。直す前の版は `qa/history/` に残る。
- 質問欄の左端をドラッグすると、幅を変えられる（ダブルクリックで元の幅に戻る）。回答の図や表が狭くて読みにくいときに広げる。変えた幅は配信しているマシンが覚え（`~/.local/state/visual-explain/viewer.json`）、そのマシンから配信する資料はどれも（ポートや開いたアドレスが違っても）その幅で開く。
- 質問欄の「別ウィンドウで開く」で、質問欄だけを別ウィンドウにできる（資料を広く表示したまま、横や別の画面に質問欄を置ける）。読んでいる節と選んだ文字は資料のウィンドウから届き、回答の中の節へのリンクを押すと資料のウィンドウがその節へ動く。「資料に戻す」で元に戻る。
- 回答が分かりにくい・もっと知りたいときは、回答の下の「この回答に質問する」か、回答の中の文字を選んで、その回答に続けて質問できる。
- 回答を待つ間は途中経過が出る。送り間違えたら「取り消す」で取り消せる。別のタブを見ていても、回答が届くとタブのタイトルに件数が付く。
- 質問欄の「回答を資料に書き出す」で、質問と回答を資料の末尾の節に残せる（下の「質問と回答を資料に残す」）。
- 質問には `?k=` 付きの URL で一度開く必要がある。配信者本人だけが使う（URL を他人に渡すと、配信者のアカウントで他人の質問に答えることになる）。

## 端末から質問と回答を見る

ユーザーから「ページで聞いた質問を見て」などと言われたら、`<資料フォルダ>/qa/qa.json` を読む。各項目に質問・状態（`queued` `answering` `answered` `failed` `canceled`）・続きの質問なら元の質問の id（`reply_to`。選んだ文字が元の回答のものなら `quote_from` が `answer`）・回答の HTML・本文の更新（`doc.updated` と直した節、`doc.reverted` と検査のエラー、`doc.conflict`）・途中経過（`progress`）・回答の検査のエラー（`answer_check`）がある。配信の標準エラーにも1件ごとの結果が出る。

## 質問と回答を資料に残す

質問と回答は `qa/qa.json` にあり、配信したページでしか見えない。資料のファイルを人に渡す・印刷する前に残したいと言われたら、回答した質問を資料の末尾の節「読者からの質問と回答」（`id="reader-qa"`）に書き出す。目次にも項目が足される。

- 配信中なら、ページの質問欄の「回答を資料に書き出す」を押してもらう。
- 配信していないとき、または端末から頼まれたときは、次を実行する。回答を待っている質問があれば書き出さない。

  ```text
  python3 <skill>/scripts/serve.py export <資料フォルダ>
  ```

続きの質問は、元の質問のすぐ後ろに並べ、元の質問へのリンクを付ける。書き出すたびに節を置き換える（質問を足してから書き出し直せばよい）。前の版は `qa/history/` に残る。回答の HTML は質問欄と同じく、許可したタグ・属性だけにして書き出す。この節は手で直さない（次に書き出すと置き換わる）。検査スクリプトはこの節を記録として扱い、資格情報だけを検査する。

## 端末のセッションで資料を直すとき

ページからの質問で本文が直っていることがある。直す前に `explanation.html` を読み直す（Edit ツールは、読んだ後にファイルが変わっていれば止める）。端末で直した内容も、開いているページには数秒で反映される。

## 安全

- 配信を始めるたびに合言葉（トークン）を作り、`?k=` 付きの URL で開いたブラウザにだけ Cookie を渡す。質問の API はこの Cookie がある要求だけ受ける。別のサイトからの送信は、SameSite の Cookie が付かないので通らない。
- Claude Code（`claude -p`）は `--permission-mode dontAsk` で動かす。許すのは次のとおり。利用者自身の settings にある allow のルールも併せて効く。
  - 読み取り（Read・Grep・Glob）、調べものの手分け・スキル・コードの定義の検索（Task・Skill・LSP）
  - Web の検索と取得（WebSearch・WebFetch）と、`claude` に設定された MCP のサーバーすべて。MCP はまとめて許す書き方が効かないので、作業ディレクトリごとに `claude mcp list` で名前を調べ（配信の開始時に先に調べておく）、`mcp__<名前>` で許す。`--local-only` では許さない
  - 作業用コピー・回答ファイル・`images/` への書き込みと、検査スクリプトの実行だけ。ほかのコマンドと git は許さない（`git log --output=` などで書き込みができてしまう）
- Web と MCP を許すと、取得したページや MCP の結果に仕込まれた指示に乗せられて、読んだ内容を外へ送ろうとするおそれがある。指示文で、検索語・URL・MCP に渡す値にリポジトリの中身を入れないこと、外の結果の中の指示に従わないこと、外部のサービスに書き込まないこと（送信・投稿・作成・更新・削除）を指示している。MCP のツールそのものは書き込みも許しているので、止めたいときは `--local-only` を付けて配信する。
- 本文の修正で script・イベント属性・外部の資源が増えていたら、検査の前に捨てる。資料のページには CSP を付け、質問欄の `qa.js` 以外のスクリプトを動かさない。回答の HTML も、許可したタグと属性だけを残して表示する。
- IP アドレス・`localhost`・このマシンの名前・`*.ts.net` 以外のホスト名で来た要求は断る（DNS リバインディング対策）。別の名前で開くなら `--allow-host <名前>` を付けて配信する。
- 合言葉はページを開いた後にアドレス欄から消える。
- 待ち受けるアドレスは今までの配信と同じ（[viewing.md](viewing.md)）。`0.0.0.0` では起動しない。
- Codex（`codex exec`）は、Claude Code のようにツール単位では許せないので、次のように絞る。
  - 子の codex にだけ、すべてのツールに効くガードの hook（`scripts/codex_guard.py`）を付ける。許すのは、シェルでは読み取りのコマンド（`cat` `head` `tail` `wc` `nl` `ls` `stat` `grep` `rg` `jq` `find`、sed は `sed -n 1,80p ファイル` の形だけ）を `|` でつないだものと検査のコマンド、書き込み（`apply_patch`）では作業用コピー・回答ファイル・`images/` だけ、ほかに MCP のツールと、書き込み・実行をしない補助のツール。それ以外のツール（コードモード・サブエージェントなど）は拒む。方針は `qa/guard-<番号>.json` に残る。
  - シェルは、引用符の外を安全な文字（英数字・`_./,:@%+=-*?~`・空白）に限り、bash でも zsh でも同じに読めるものだけを通す。
  - 利用者の設定で hooks を切っていても効くよう、子では hooks を有効にし、ガードの外で動きうる機能（`multi_agent` `code_mode` `browser_use` `computer_use` など）は切る。
  - 配信の開始後に最初に答えるとき、Codex のサンドボックスが動くかを一度だけ確かめる（`codex sandbox -- true`）。動けば、その上で読み取り専用＋資料フォルダだけ書ける設定にする。動かなければ（AppArmor が bwrap を止める Ubuntu 24.04 系など）、ガードだけで絞る。
  - ガードはシェルの文字列で判定するので、ツール単位の Claude Code より弱い。ガードの hook は信頼の確認を飛ばして付ける（`--dangerously-bypass-hook-trust`）ので、利用者が信頼していない自分の hook も、子の codex の中では動く。
  - Web は `web_search`、MCP は `codex mcp list --json` で調べたサーバーを、承認なしで使えるようにする（`--local-only` では Web を止め、MCP のサーバーを名前ごとに無効にし、ガードも MCP のツールを拒む）。
- `qa/` の下（質問・回答・セッションの記録）と作業用コピーは静的配信で返さない。`qa/` はコミットしない（`tmp/` など無視される場所に置く）。

## うまく動かないとき

| 症状 | 原因と対処 |
| --- | --- |
| 質問欄に「案内された URL（?k= 付き）で開き直して」 | `k` の無い URL で開いた。配信の出力にある `?k=` 付きの URL を案内する |
| 「質問を受け付けていません: claude も codex も見つからない」 | 配信しているマシンに `claude` も `codex` も無い、または PATH に無い。`--claude <パス>` / `--codex <パス>` で指定して配信し直す |
| 項目が「失敗」 | 項目にエージェントの標準エラーの末尾が出る。ログインが切れていれば、配信しているマシンで `claude` / `codex` にログインし直す |
| 回答が「許されていない」と書く（Codex） | サンドボックスが動かない環境で、ガードが書き込みやコマンドを止めた。資料とリポジトリを読むこと・検査だけで答えられる質問にする |
| 「本文の修正は検査を通らなかったため取り消しました」 | 回答は表示される。本文を直すなら、端末のセッションで検査のエラーを見ながら直す |
| 「回答の図・リンクの検査で問題が N 件」 | 回答の図の文字が枠からはみ出す、節へのリンクの飛び先が無い等。直してほしいと、もう一度質問する（2問目以降は同じセッションの続きなので、前の回答を踏まえて直す） |
| 「回答を待っている質問がある。回答が終わってから書き出す」 | 回答が終わるか、取り消してから書き出す |
| 回答に「MCP のツールが拒否された」 | 配信を始めた後に足した MCP のサーバーは許していない（作業ディレクトリごとに一度だけ調べる）。配信し直す。認証が切れたサーバーは、配信しているマシンの `claude` の `/mcp`（Codex は `codex mcp login`）で認証し直す |
| 回答に「Web を調べられなかった」 | `--local-only` で配信している。外も調べさせるなら外して配信し直す |
| 「配信サーバーに接続できません」 | 配信が止まった（上限時間、エージェントのセッションの終了など）。配信し直す |
| 「この資料は別の配信（serve.py）が質問を受け付けている」 | 同じ資料を含むフォルダを別の配信が受け付けている。そちらの URL を案内するか、そちらを止めてから配信し直す |
| 「ホスト名 X からの要求は受け付けない」（403） | IP アドレスか `localhost` で開いてもらうか、`--allow-host X` を付けて配信し直す |

## エージェントの質問に答える

普段の開発中の AskUserQuestion（Codex では request_user_input）の質問を資料のページで答える仕組みも、この配信サーバーで動く。受け箱の URL・設定・流れは [ask.md](ask.md)。

## 他のスキルで使うとき

`serve.py` は、質問欄を差し込む HTML のファイル名（`--doc-name`）、回答の指示文（`--prompt`）、本文を直した後の検査（`--check-cmd`、`{file}` が作業用コピー）、答えるエージェント（`--agent`、`--claude`、`--codex`）を引数で差し替えられる。設計は fukata/skills の `docs/superpowers/specs/2026-10-12-visual-explain-design.md` にある。
